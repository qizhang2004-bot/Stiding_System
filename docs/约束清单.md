# 排班算法约束清单（`project/app/scheduler/scheduling.py`）

本文把 CP-SAT 排班模型里**实际施加的每一条规则**列出来，标明是硬约束还是软目标、
由哪个配置项控制、以及反馈给用户的中文诊断。

- 模型对象：`x[人,天,班次]`（是否上该班）、`y[人,天]`（当天是否上班）、`r = 1 − y`（是否休息）、
  `z[人,天,岗位]`（当天被指派的岗位）。
- 排班周期：每月 25 号起算，长度 `days`（28~31 天）。
- 求解：两阶段（先最大化达标人数，再词典序多目标），单线程 + 配置派生随机种子 ⇒ **同配置同结果**。

---

## 一、硬性约束（必须全部满足，任一不满足即无解）

| # | 约束 | 代码位置 | 配置项 | 说明 |
| --- | --- | --- | --- | --- |
| H1 | 每天下井总人数 == 应上人数 | `build_model` 约束 1 | `daily_total` | 每天所有班次人数之和恒等于该值。 |
| H2 | 一人一天最多一个班 | 约束 2 | 内置 | `Σ_s x[人,天,s] ≤ 1`，且 `y = Σ_s x`。 |
| H3 | 岗位人数条件 | 约束 3 | `role_req` | 每天该岗位被指派人数满足 `≥` / `≤` / `=`，统计 `z` 而非上班天数。 |
| H4 | 一人一天只占一个岗位名额 | 约束 3 | 内置 | `Σ_role z[人,天,role] ≤ y[人,天]`。未被指派岗位的上班人员按「普通」岗补位，不占任何岗位配额——否则 `=` 会因名额不足而无解。 |
| H5 | 单休禁止（连休 ≥ 最短休息） | 约束 4 | `rest_block.min` | 禁止「上班 + 若干天休息 + 上班」里休息天数 < `min`；含月初（休息段 + 上班）与月末（上班 + 休息段）边界。系统强制 `min ≥ 2`。 |
| H6 | 连休不超上限 | 约束 4 | `rest_block.max` | 任意 `max+1` 天窗口内休息天数 ≤ `max`。 |
| H7 | 连续上班 ≥ 最短 | 约束 4b | `work_block.min`（默认 2） | 禁止「休息 + 若干天上班 + 休息」里上班天数 < `min`；含月初/月末边界。 |
| H8 | 连续上班 ≤ 最长 | 约束 4b | `work_block.max` | 任意 `max+1` 天窗口内上班天数 ≤ `max`。默认 `max = 周期天数 // 3 − 最短休息天数`；`max = 0` 表示不设上限。 |
| H9 | 班次硬性规则 | 约束 5 | `worker_default_shift` | 人员导入/上传的默认班次 = 该人唯一可排班次，其余班次的 `x` 直接置 0（是硬规则，不是偏好）。未指定默认班次的人不受限制。 |
| H10 | 逐人班数硬性上下限 | 约束 6 | `worker_shift_req[name].min/max` | 显式给出时作为硬约束。 |
| H11 | 专人专项最少上班天数 | 约束 6 | `worker_rules[name].work_days` | 该人的硬性下限，**取代**班组默认目标；且不套用「豁免模式」的 `min == max` 夹紧。 |
| H12 | 专人专项休息日范围 | 约束 4 / 4b | `worker_rules[name].rest_block` | 该人用自己的连休 `[min,max]` **完全取代**班组默认值；其连续上班上限按自己的最短休息天数重算（`周期天数÷3 − min`），避免与休息要求自相矛盾。 |

### 豁免人员（`exempt_workers`）的例外

被列为豁免的人员**不参与** H5、H6、H7、H8、H11（休息规则、连续上班规则、最少上班天数），
可以 0 班或任意作息；其 `worker_rules` 与 `person_overrides` 同样不生效。
豁免人员只受 H1~H4 与 H9 约束。

## 二、软性目标（词典序多目标，按优先级依次优化）

OR-Tools ≥ 9.9 支持连续多次 `minimize` 即构成词典序优化，**先写者优先级更高**：

| 优先级 | 目标 | 作用 |
| --- | --- | --- |
| 1 | 每人班数贴近目标（偏离最小） | `Σ(over + under)` 最小 |
| 2 | 非豁免人员之间班数均衡 | `max_c − min_c` 最小 |
| 3 | 未达标者尽量接近目标且互相均分 | `(days+2)·max_s − min_s`，层内先压 `max_s` 再均分 |
| 4 | 软性避免单休 | 仅在未启用 `rest_block` 硬约束时生效 |
| 5 | 豁免人员尽量少且均衡 | `(days+2)·exempt_max − exempt_min` |

### 多目标必须逐层求解（重要实现约束）

CP-SAT **不支持**「连续多次 `minimize()` 即词典序」：实测 OR-Tools 9.15 只有
**最后一次** `minimize` 生效，前面写的目标会被静默丢弃。因此
`_solve_lexicographic()` 采用逐层求解：每层求出最优值后，把「该目标 == 本层最优值」
加成硬约束，再优化下一层，从而真正固定高优先级。

优先级（从高到低）：

1. 每人班数贴近目标（偏离最小）
2. 非豁免人员之间班数均衡
3. 未达标者尽量接近目标、且未达标者之间均分
4. 软性避免单休（仅未启用连休硬约束时）
5. **剩余班次在「豁免人员 + 只设下限的专人专项人员」之间均分**：
   先抬高这一组里班数最少的人，再把差距压小，保证剩余班次被平分，
   而不是被少数「没有上限」的人独吞（历史 bug：豁免人员被挤成 0 班）。

### 两阶段求解

1. **阶段一**：最大化「达到最少班数的人数」（不建偏离变量，模型更小更快），
   并给每人「上 6 休 4」错峰 hint 加速收敛。
2. **阶段二**：以 `Σreached ≥ 阶段一最优值` 固定达标人数，按上表词典序优化，
   以阶段一解作为 hint 起步。阶段二失败会自动回退到阶段一解（同为合法解）。

## 三、可行性预检与容量预估（纯计算，不求解）

`validate_config()` 做的是**必要条件**检查，用于提前给出中文诊断：

| 检查 | 触发条件 |
| --- | --- |
| 结构完整性 | 缺 `workers` / `shifts` / `days ≤ 0` / 缺 `daily_total` |
| 总容量 | `每天人数 × 天数 > 总人数 × 天数` |
| 岗位持有人容量 | `≥`/`=` 条件下 `需求人天 > 持有人数 × 天数` |
| 岗位无人 | 该岗位没有任何匹配人员 |
| 硬性最低班数合计 | 各人硬性下限之和（含专人专项）`>` 周期总班次 |
| 岗位保证量缺口 | 非豁免该岗位人员的硬性保证人天 + 豁免可补人天 `<` 岗位需求人天 |
| 休息规则合法性 | `rest_block.min < 1` 或 `max < min` |
| 专人专项合理性 | 连休下限 ≥ 周期天数；或要求的上班天数在规则下**排不出来** |
`capacity_analysis()` / `capacity_quick()` 用纯算术给出「最多能满几人 / 需豁免几人」：
`最多能满 = floor(总班次 ÷ 目标班数)`，页面秒开。

### 可达上班天数是离散的（重要）

受 H5~H8 两端规则限制，一个人实际能排出的上班天数**不是连续区间**。
例如 30 天周期、连休 3~4 天、连续上班 2~7 天时只能排出 **10~21 班**，
22~30 班全部排不出来（22 班要切成 4 段上班，4 段之间至少夹 3 段休息共需 ≥9 天休息，
而 30−22=8 天休息不够）。

`reachable_work_days_bounded()` 用逐日 DP 精确枚举可达天数，状态为
`(已排天数, 当前是上班还是休息, 当前连续长度)`，只在「当天与前一天不同」或「序列结束」时
校验上一段长度，因此与模型施加的边界规则**完全一致**（已对照暴力枚举逐例验证）。
`validate_config` 用它拦截排不出来的「至少上班」要求，并提示不小于该数的可达天数。
